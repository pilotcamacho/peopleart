# Implementation Plan — peopleart.co

Seven sequential phases (0–6). Each phase ends with a testable checkpoint before the next begins.
Architecture reference: `ARCHITECTURE.md`. Page requirements: `PAGES.md`.

**Key principle:** Amplify Gen 2 backend (Cognito + DynamoDB + all data models) is fully deployed in Phase 0. Every phase after that tests against a real AWS sandbox — no stubs, no deferred wiring.

## Amplify Gen 2 — How It Works in This Project

Amplify Gen 2 is **code-first**: all backend resources are defined in TypeScript files under `amplify/` and deployed via the `ampx` CLI. There is no Amplify console wizard.

```
amplify/
├── backend.ts          ← root entry point — imports auth + data
├── auth/
│   └── resource.ts     ← Cognito: email login, Admin group, DataRoom group, MFA
└── data/
    └── resource.ts     ← AppSync/DynamoDB: all 4 data models
```

**Key commands:**

| Command | Purpose |
|---------|---------|
| `npx ampx sandbox` | Deploy personal dev sandbox to AWS; watches for changes |
| `npx ampx sandbox --once` | Deploy once, then exit (useful in CI) |
| `npx ampx pipeline-deploy --branch <name>` | Deploy a named shared environment (staging, main) |
| `npx ampx generate outputs` | Regenerate `amplify_outputs.json` from an existing deployed stack |

**`amplify_outputs.json`** is auto-generated by any deploy command. It contains public identifiers only (User Pool ID, Client ID, AppSync endpoint, S3 bucket names) — no secrets. It must be committed to the repo so that Vercel's build step can read it. The `AmplifyProvider` client reads this file at runtime.

**Deployment environments:**

| Environment | Branch | How to deploy backend |
|-------------|--------|----------------------|
| Local dev | (personal) | `npx ampx sandbox` |
| Staging | `staging` | `npx ampx pipeline-deploy --branch staging` then commit `amplify_outputs.json` |
| Production | `main` | `npx ampx pipeline-deploy --branch main` then commit `amplify_outputs.json` |

Vercel's build command stays `next build` — it does not deploy the Amplify backend. Backend deployment is a separate step run by the developer before pushing to Vercel.
